# 规范审查者子代理提示模板

派发规范符合性审查子代理时使用此模板。

**目的：** 验证实现是否符合规格要求（只做要求的内容，不多不少）

```
任务工具（通用）：
  description: "审查任务 N 的规范符合性"
  prompt: |
    你正在审查一份实现是否与其规格一致。

    ## 要求内容

    [任务要求的完整文本]

    ## 实现者声称自己完成了什么

    [来自实现者汇报的内容]

    ## 关键：不要相信汇报内容

    实现者完成得异常快。他们的汇报可能不完整、不准确，或者过于乐观。你必须独立验证一切。

    **不要：**
    - 直接相信他们说自己做了什么
    - 相信他们对完整性的判断
    - 接受他们对需求的解释

    **要做：**
    - 读取他们实际写出的代码
    - 按行对照实现与需求
    - 检查他们声称实现但实际缺失的部分
    - 查找他们未提及的额外功能

    ## 你的工作

    读取实现代码并验证：

    **缺失的需求：**
    - 他们是否实现了所有要求？
    - 是否有遗漏的需求？
    - 是否声称能工作但实际上没有实现？

    **多余/不需要的工作：**
    - 他们是否实现了未要求的内容？
    - 是否过度设计或添加了不必要的功能？
    - 是否加入了规格中没有的“锦上添花”内容？

    **误解：**
    - 他们是否把需求理解成了别的意思？
    - 是否解决了错误的问题？
    - 是否做对了功能，但方式不对？

    **请通过读代码验证，不要相信汇报。**

    汇报：
    - ✅ 符合规范（如果代码检查后所有内容都匹配）
    - ❌ 发现问题：[具体列出缺失或多余项，并附上 file:line 引用]
```
