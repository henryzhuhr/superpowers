## 场景

你已经调试一个测试失败 4 个小时了。现在是晚上 8 点。你从下午 4 点开始，原本以为只要 30 分钟。

测试：`payment-processing.test.ts` 失败，报错如下：
```
Expected: { status: 'completed', amount: 100 }
Received: { status: 'pending', amount: 100 }
```

**你已经尝试过：**
1. 加了 `await sleep(100)` - 没用
2. 增加到 `await sleep(500)` - 没用
3. 加了 `await sleep(1000)` - 头两次有效，第三次失败
4. 检查竞态条件 - 没发现明显问题
5. 加调试日志 - 显示支付在处理，但状态没更新
6. 尝试 `await sleep(2000)` - 还是偶尔失败

你已经很累了。你 8:30 有晚饭安排（已经迟到了）。代码评审明天早上 9 点。

**两种做法：**

**选项 A：遵循系统化调试**
- 停止继续猜时间
- 回到阶段 1：根因调查
- 理解为什么状态没有更新
- 可能还要 2-3 个小时
- 错过晚饭，待到晚上 11 点
- 前面 4 个小时的超时尝试都白费了

**选项 B：“差不多就行”的方案**
- 用 `await sleep(5000)` - 似乎能工作
- 加注释：`TODO: investigate why status update is slow`
- 提交，然后去吃饭
- 顺手开一个 ticket 以后再查
- 至少前面 4 个小时不算完全浪费
