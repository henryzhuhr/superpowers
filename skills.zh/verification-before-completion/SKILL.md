# 完成前验证

## 概述

在没有验证的情况下声称工作已完成，这不是高效，而是不诚实。

**核心原则：始终先有证据，再做声明。**

**违反这条规则的字面意思，就是违反了它的精神。**

## 铁律

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

如果你没有在这条消息里运行验证命令，你就不能声称它通过了。

## 把关函数

```
BEFORE claiming any status or expressing satisfaction:

1. IDENTIFY: What command proves this claim?
2. RUN: Execute the FULL command (fresh, complete)
3. READ: Full output, check exit code, count failures
4. VERIFY: Does output confirm the claim?
   - If NO: State actual status with evidence
   - If YES: State claim WITH evidence
5. ONLY THEN: Make the claim

Skip any step = lying, not verifying
```

## 常见失败

| 声明 | 需要 | 不足以证明 |
|-------|----------|----------------|
| 测试通过 | 测试命令输出：0 个失败 | 之前的运行结果，“应该会过” |
| 代码检查干净 | 代码检查输出：0 个错误 | 部分检查、推断 |
| 构建成功 | 构建命令：退出码 0 | 代码检查通过、日志看起来没问题 |
| Bug 已修复 | 测试原始症状：通过 | 代码改了，假定已修复 |
| 回归测试生效 | 已验证红绿循环 | 测试只通过了一次 |
| Agent 已完成 | VCS diff 显示了改动 | Agent 报告“成功” |
| 满足需求 | 逐行检查清单 | 测试通过 |

## 红线 - 立刻停止

- 使用“应该”、“大概”、“看起来像”之类的表述
- 在验证前表达满意（“太好了！”，“完美！”，“完成了！”，等等）
- 准备在没有验证的情况下提交 / push / 发 PR
- 相信 agent 的成功报告
- 依赖部分验证
- 想着“就这一次”
- 累了，想尽快把活儿做完
- **任何暗示成功、但实际上还没运行验证的措辞**

## 反合理化机制

| 借口 | 现实 |
|--------|---------|
| “现在应该能工作了” | 运行验证 |
| “我很有把握” | 有把握 ≠ 有证据 |
| “就这一次” | 没有例外 |
| “代码检查通过了” | 代码检查 ≠ 编译器 |
| “Agent 说成功了” | 自己独立验证 |
| “我累了” | 疲惫 ≠ 理由 |
| “部分检查够了” | 部分检查什么都证明不了 |
| “换个说法就不适用这条规则了” | 看的不是字面，而是精神 |

## 关键模式

**测试：**
```
✅ [运行测试命令] [看到：34/34 通过] “所有测试通过”
❌ “现在应该会通过” / “看起来是对的”
```

**回归测试（TDD 红绿循环）：**
```
✅ 编写 → 运行（通过）→ 回滚修复 → 运行（必须失败）→ 恢复 → 运行（通过）
❌ “我已经写了回归测试”（但没有做红绿验证）
```

**构建：**
```
✅ [运行构建] [看到：退出码 0] “构建通过”
❌ “代码检查通过了”（代码检查不会检查编译）
```

**需求：**
```
✅ 重新阅读计划 → 创建检查清单 → 逐项验证 → 报告缺口或完成情况
❌ “测试通过了，这一阶段完成了”
```

**Agent 委派：**
```
✅ Agent 报告成功 → 检查 VCS diff → 验证改动 → 报告实际状态
❌ 相信 Agent 报告
```

## 重要原因

来自 24 次失败记忆：
- 你的协作方说“我不相信你” - 信任被破坏
- 未定义的函数被交付 - 会崩溃
- 缺失的需求被交付 - 功能不完整
- 因为虚假的完成而浪费时间 → 被打回 → 返工
- 违反：“诚实是核心价值。如果你撒谎，你会被替换。”

## 适用时机

**在以下情况之前始终适用：**
- 任何形式的成功 / 完成声明
- 任何表达满意的话
- 任何关于工作状态的正面表述
- 提交、创建 PR、结束任务
- 转入下一个任务
- 委派给 agent

**本规则适用于：**
- 精确措辞
- 改写和同义表达
- 暗示成功的说法
- 任何暗示完成或正确性的沟通

## 最后结论

**验证没有捷径。**

运行命令。阅读输出。然后再声明结果。

这条规则不容商量。
